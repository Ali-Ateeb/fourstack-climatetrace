ClimateTrace is a local environmental observation integrity prototype for the IEEE ClimateChain hackathon. Community projects may exchange small logs of solar generation or rainfall before they have a shared data platform. This tool gives them a way to notice changes against a fingerprint kept separately. This is an edited walkthrough of actual browser captures with synthetic Windows narration. Every example reading is invented. No real sensor data, carbon credit, emissions reduction or environmental impact is claimed.

The example has three observations: two solar generation readings and one rainfall reading. Each includes an identifier, an explicit UTC timestamp, site, metric, numeric value, unit and source note. The notes say these are invented examples, not sensor measurements. The prototype supports solar generation and electricity consumption in kilowatt hours, and rainfall in millimeters. Numeric values must be finite and nonnegative. The application checks real dates and matching units, but cannot tell whether a person supplied a truthful measurement.

Sealing normalizes each reading and hashes it with its sequence number and the previous record hash. The last hash becomes the root fingerprint. The same complete normalized log produces the same root. The download contains all three records, previous pointers and hashes. An actual browser download was inspected. Keep the root in a separate trusted place before sharing the bundle. The prefilled root here is only a convenience for this demonstration; it does not create independent trust or publish anything to a blockchain.

The simulate button changes the first reading by one without updating its hash. Verification reports an integrity mismatch at reading one. This catches an accidental edit or a change made without rebuilding the evidence. It does not identify the person who changed it. Seven core tests also cover changed previous pointers, duplicate identifiers, invalid units and dates, truncated logs and malformed evidence. These are narrow prototype checks, not a general security audit.

Without an independent root, the original bundle passes its internal chain check, but the interface explicitly warns that a rebuilt chain could pass too. Someone who changes values and recomputes every hash can make another internally consistent bundle. Our tests demonstrate this limitation rather than hide it. Neither a hash chain nor a matching fingerprint proves that the observation happened, that a sensor was calibrated, or that a climate claim is valid.

Here we supply a different sixty four character fingerprint. The internal records are unchanged, but verification rejects the independent root mismatch. In practice this comparison only helps if the original root came from a trusted channel and could not be replaced along with the data. ClimateTrace currently has no author signatures, public anchoring, external timestamp, consensus network or access control. Those would need separate design and evaluation. There is no integrated AI model or automatic climate judgment.

Adding a fourth observation invalidates the old seal and hides its download button, so an old export cannot be mistaken for the updated log. Duplicate identifiers are rejected. The verifier remains separate, so an earlier pasted bundle can still be reviewed deliberately. All processing stays in the browser and no data persists after reload. Codex assisted with code, tests, documentation and this video. This is a small data verification proof of concept, not production climate infrastructure. Next steps include trusted external root publication, authenticated authors and field evaluation; none is implemented or claimed today.
